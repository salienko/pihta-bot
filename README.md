# pihta-bot

Telegram бот бронирования одной бани «Пихта». Python 3.11, aiogram 3.31.0, PostgreSQL. Основные бизнес правила закреплены в документе «Идея только бота» 1.1 и уточнении владельца о запросе платёжной ссылки через администратора.

Пять фиксированных двухчасовых сеансов, час уборки после каждого, ручные 3–5 часов, снимки цены, дети и вместимость, услуги с подтверждением, предоплата и доплаты с ручной сверкой, отмена и перенос по решению администратора, постоянные таймеры и напоминания. PayKeeper не подключён: администратор передаёт гостю ссылку через бот; возвраты только регистрируются для ручного рассмотрения.

## Настройки Bothost

`BOT_TOKEN` — существующий секрет, не менять и не публиковать.

`DATABASE_URL` — PostgreSQL DSN в секретных настройках хостинга.

`OWNER_TELEGRAM_ID` — числовой ID владельца; обязательный при подключении базы.

`BOOKING_ENABLED=true` — включать только после проверки подключения и функциональных тестов. Без базы и с выключенной записью бот сохраняет информационное меню.

`BACKUP_DIR` — необязательно, по умолчанию `/app/data/backups`.

Запуск: `python bot.py`. Только один polling процесс. Дополнительно приложение удерживает advisory lock PostgreSQL. Таблицы создаются идемпотентно в выбранной базе. Нельзя подключать другую систему бронирования к этим таблицам с прямой записью в обход сервиса.

## Проверки

`python -m unittest discover -v` — правила и интерфейс. PostgreSQL тесты требуют `TEST_DATABASE_URL`: создают уникальную тестовую схему и удаляют только её после проверки. Не используют рабочую `DATABASE_URL`. Проверки с отсутствующей тестовой БД пропускаются и не считаются выполненными.

Все изменения занятости и денег сериализуются транзакцией с блокировкой строки единственного ресурса. Гостевое время и уборка проверяются вместе; истечение, перенос, ручная бронь и блокировка используют тот же механизм. Поступления не дублируются благодаря уникальному claim_id. Заявление оплаты не является платежом.

## Резервные копии и откат

`python backup.py` — согласованный логический снимок без токенов и DSN. Автоматические локальные копии каждые 6 часов не заменяют внешнюю копию и тест восстановления. В публичный репозиторий не добавлять базы, снимки, логи, Telegram ID владельца или секреты.

Исходный информационный бот: commit `18effdf8e88e628e8ab5c858d61cc3254477d943`. При аварийном откате остановить новый процесс, вернуть этот commit и запустить его. Не удалять PostgreSQL и снимки. Старый информационный бот не обрабатывает новые записи; администратор продолжает учёт по сохранённой базе.

Инструкция администратора: [OPERATIONS.md](OPERATIONS.md).
